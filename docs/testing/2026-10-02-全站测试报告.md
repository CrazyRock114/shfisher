## S1 被测系统画像（SFDIPOT 摘要）

| 维度 | 内容 |
| --- | --- |
| 结构 | FastAPI 后端（scoring/tide/alerts/log_db/data 五模块）+ 零构建前端（app.js ≈900 行）+ 数据文件（fishing_spots.json 47 条）+ SQLite |
| 功能 | 六页：出钓指数（100 分制评分）/ 潮汐水文（转流窗口）/ 钓点地图 / 钓鱼日志 / 装备清单 / 合规速查；8 个 API |
| 数据 | 钓点 JSON（人工调研维护）、水质/合规/装备常量、日志 SQLite（用户输入）、实时外部源（天气/潮汐/水位/预警） |
| 接口 | Open-Meteo、上海海事局 HTML、市水务局 JSON、市预警发布中心 warn.js —— 均有缓存与错误处理 |
| 平台 | 桌面浏览器（CDN 依赖 Chart.js/Leaflet）；本地单机部署 |
| 运营 | 单用户个人应用；无鉴权、无多租户 |
| 时间 | 禁渔期（2.16–5.16）、季节评分窗口、感潮时段、月相——多处日期/时区敏感逻辑 |

冒烟结论：服务可启动，8 API 全 200，既有 40 项单测全绿（复跑确认）。

## S3 策略

- **分层**：后端测试金字塔（单元边界值为主 + TestClient API 集成）；前端按内容站分层扫掠 L1 结构 / L2 数值 / L5 一致性 / L6 交互（九条铁律 + 状态转移）+ SBTM 探索会话。
- **Oracle 来源**（规格，非实现）：docs/03 第二节评分规则表；docs/02 潮汐钓法语义（平潮=高低潮前 40min~后 30min，转流初期=平潮后 2.5h）；docs/00 合规表；README 计数声明。
- **性质断言最小集**：评分—score∈[0,100] 且非 gate 时=parts 之和、parts 均在各自权重域、gate⇒score=0；潮汐—phases 无缝覆盖 [0,1440] 无重叠、label∈4 种、每个 stand 产生平潮(70min)+转流(150min)（截断除外）。
- **断言强度红线**：存在性占比 < 40%（S7 用脚本统计）。

### 残余风险声明

1. 外部数据源（Open-Meteo/海事局/水务局/预警中心）自身正确性与可用性不在测试范围，页面有错误横幅兜底；
2. 钓点坐标为概略值（数百米级），到达需现场确认（数据层已标注）；
3. 前端无 CI 化浏览器测试环境（本机无 node/playwright），XSS/交互疫苗以"探针脚本入仓 + 会话内前后对照"形式存在，可人工重跑（探针代码见本报告附录）；
4. D5 跨午夜转流窗口截断；
5. 无鉴权/无 CSRF——单机个人应用口径下接受；
6. 移动端适配未测。
